# 20261122-192607 · TO-BE 기반 React 구매·운영 검증

대상은 [React 프로토타입](../../prototypes/react-storefront/README.md)이다. [이전 검수](20261122-180421-react-storefront.md)의 25,000원 주문과 모바일 화면을 회귀 기준으로 삼았다. 이전의 전체 주문 취소와 연락처 단순 대조는 품목별 처리 및 목적별 인증으로 교체했다. [설계별 대응](../../prototypes/react-storefront/design-coverage.md)은 구현 위치를, 아래 기록은 실제로 확인한 범위를 설명한다.

## 실제 Chrome 조작

| 흐름 | 관찰한 결과 |
| --- | --- |
| 계정·상품 | 모바일에서 아이보리 옵션 2개를 담았다. 가입 시 기존 번호로 실패한 뒤 재발급 번호로 인증, 로그인, 배송지 저장, 비밀번호 변경, 탈퇴와 다시 로그인해야 하는 경로를 확인했다. |
| 구매·결제 | 타월 2개와 2,000원 쿠폰에 일반 배송은 25,000원, 도서 배송은 28,000원이었다. 배송 제한 주소에서 진행이 차단됐다. 미확정 거래를 새로고침한 뒤 원거래를 조회해 승인하고 계약 파일 다운로드·영수증·주문 상담을 확인했다. 1개 취소 예상 환불은 11,000원이었다. |
| 비회원 구매 | 주문 연락처와 다른 수취 연락처를 입력했다. 예약 지연 후 동일 주문으로 복구, 카드 거절 후 재주문 경로를 확인했다. 인증 후 15분을 넘겨 주문서 작성 권한이 만료되면 재인증 화면이 열리고 주문은 생성되지 않았다. |
| 두 탭 경합 | 견적을 연 뒤 다른 탭에서 상품가 12,000원을 15,000원으로 바꿨다. 새 견적에 동의한 뒤에만 18,000원 결제가 가능했다. 양쪽에서 같은 마지막 1개를 취소하려고 하면 한쪽의 잔여 수량이 0이 되고 접수는 1건이었다. |
| 역할과 원장 | 운영 2차 인증, 판매가 변경 후 과거 단가 보존, 실사 수량 하한, 부분 취소 후 잔여 포장·인계와 물류 역할의 환불 메뉴 거절을 확인했다. 재무 화면에서 환불 금액 불일치를 보류한 뒤 일치하는 원거래로 종결했다. |
| 회수·재무·발송 | 방문 실패와 재방문, 실제 수거, 잘못 도착한 SKU 조사, 입고 2개 중 양품 1개만 복귀, 24,000원 환불의 후속 전달 재개를 확인했다. 지급 명세 대사와 동일 발송 결과 재조회로 고객 환불·발송이 추가되지 않았다. |
| 운영자 경합 | 같은 상품을 연 담당자의 늦은 수정이 최신 15,000원 가격을 덮지 않았다. 환불 폼을 연 상태에서 권한을 회수하자 해당 담당자의 처리 효과가 0건이었고 다른 재무 담당자가 원신청을 인수했다. |
| 운임·표시본 | 새 운임과 우편번호 권역이 장바구니·주문서에 반영됐다. 주문 중 운임 변경 시 재동의가 필요했고 다음 정책의 마감 시각·운임 변경 뒤에도 계약의 v3·17:30·7,500원은 유지됐다. 8월 31일 종료된 이전 표시본만 다음 해 2월 28일에 정리되고 현재 표시본과 원주문은 남았다. |
| 검수 도구 | X05에서 C→B→A 취소 뒤 A를 재전송해도 32,003원 전액 환불 한도 안에서 종결됐다. X06에서 증빙 조회 불가 시 출고를 보류하고 이미 인계된 W-R 증빙 선택 시 승인·인계 수량을 대조했다. 일별 대사는 같은 기간을 다시 읽어도 원장 4행을 유지했다. |
| 외부 요청 | 회원·비회원 구매와 계정·검수 시나리오 실행 중 외부 호스트 HTTP 요청 및 미처리 JavaScript 오류 0건. |

## 검수 중 발견과 재검증

- 390px에서 공통 헤더의 장바구니 아이콘이 화면 오른쪽을 넘어갔다. 모바일 열 간격을 줄이고 주문 명세를 배송 폼 앞에 배치한 뒤 홈·주문서·운영 화면의 가로 넘침이 없는지 다시 확인했다.
- 독립 검토에서 비회원 선택 구매가 회원의 기존 장바구니와 섞이고 이전 탭의 인증번호가 살아 있는 문제를 발견했다. 선택 품목만 바로 구매로 이관하고 최신 발급 기준을 탭 간 공유했다. 주문별 접근·만료·회원 전환을 브라우저 회귀 테스트에 추가했다.
- 초기 실행 중 결제 복구 함수와 표시본 이력 모듈을 연결하는 사이 빌드와 브라우저 진입이 실패했다. 두 모듈이 연결된 뒤 최종 빌드와 브라우저 테스트를 재실행했다.
- 비동기 저장·인증 재발급 이전 값을 읽거나 로그아웃 완료 전에 다음 경로로 이동한 검증이 실패했다. 사용자에게 보이는 완료 상태와 저장 결과를 기다린 뒤 새로고침하도록 검사 순서를 수정했다. 최종 실행은 통과했다.
